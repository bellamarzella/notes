## Open Web Application Security Project (OWASP) Top 10

| Category                                   | Description                                                                                                                                           | Example                                                                             |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Broken Access Control                      | Restrictions are not properly implemented to prevent users from accessing others' accounts, modifying data, accessing unauthorised functionality etc. | Students are able to see and change the grades of others.                           |
| Cryptographic Failures                     | A failure due to encryption or hashing being implemented poorly, chosen badly or left out entirely.                                                   | Passwords are hashed using MD5, which is vulnerable to a rainbow table attack.      |
| Injection                                  | User-supplied data is not sanitised, filtered or validated.                                                                                           | `; OR 1=1` is accepted as a password.                                               |
| Insecure Design                            | Application isn't designed with security in mind.                                                                                                     | A store checks price on the client-side, which the client can manipulate.           |
| Security Misconfiguration                  | Proper security is present but not enabled, default settings remain unchanged or unnecessary information is left available.                           | Verbose error messages, which could allow for a `blind boolean` attack.             |
| Vulnerable and Outdated Components         | Using components that are vulnerable, unsupported or out-of-date.                                                                                     | Running a version of windows vulnerable to the `bitpixie` exploit.                  |
| Identification and Authentication Failures | Application fails to properly verify a users identity or protect their session, allowing attackers to mask as legitimate users.                       | Allowing infinite login attempts, allowing `brute force` attacks.                   |
| Software and Data Integrity Failures       | Application trusts data without verifying where they came from or whether they were tampered with.                                                    | Blindly running injected code.                                                      |
| Security Logging and Monitoring Failures   | Failure to record, detect or alert active security events, leaving the organisation blind to active attacks.                                          | Keeping logs stored locally, allowing attackers to wipe evidence of their presence. |
| Server-Side Request Forgery                | Application fetches remote resources without validating a user supplied URL.                                                                          | Hosting a payload on our own webserver and having the application fetch it.         |
